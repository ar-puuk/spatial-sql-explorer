# Test fixtures

Most files predate spec 007 and are hand-made or exported from QGIS. The
sections below cover the generated ones.

## Spec 007 fixtures

Generated by `npm run large-data -- --fixtures` (`scripts/large-data.mjs`):
synthetic parcels across Utah, 10,000 rows each, EPSG:4326. Regenerate a
file by deleting it and re-running the command, which needs a native DuckDB
CLI and, for the derived files, GDAL's `ogr2ogr`.

| File | Size | Rows | How |
|---|---|---|---|
| `parcels-10k.parquet` | 1.9 MB | 10,000 | DuckDB; GeoParquet with a `bbox` covering struct, Hilbert-sorted |
| `parcels-10k-nobbox.parquet` | 1.6 MB | 10,000 | same rows, no covering column (exercises the one-scan bbox index) |
| `parcels-10k.fgb` | 3.6 MB | 10,000 | `ogr2ogr -f FlatGeobuf -lco SPATIAL_INDEX=YES` |
| `parcels-10k.geojson` | 5.0 MB | 10,000 | `ogr2ogr -f GeoJSON -lco COORDINATE_PRECISION=6` |
| `sample.pmtiles` | 2.1 MB | n/a (tiles) | `ogr2ogr -f PMTiles -dsco MINZOOM=4 -dsco MAXZOOM=10` (GDAL 3.13) |

Columns: `parcel_id`, `parcel_code`, `zone`, `acres`, `value`, `year_built`, `geom`
(plus `bbox` in `parcels-10k.parquet`).

The large-file versions (762 MB to 5 GB) live in the gitignored
`tests/.large-data/`, from `npm run large-data`.

## Spec 026 fixtures (rasters, `raster/`)

Generated by `node scripts/fixtures-026.mjs` (GDAL; the surface is written with geotiff.js). Delete a file to
regenerate it. All are under 1 MB. The surface is smooth and known: elevation in metres at a place is
`surface(lon, lat)` (exported by the script) within a pixel's gradient, over the box 111.95°W to 111.85°W,
40.70°N to 40.78°N, with a hole of nodata (-9999) at 111.92°W to 111.90°W, 40.73°N to 40.75°N. A COG here
is `gdal_translate -of COG -co COMPRESS=DEFLATE -co BLOCKSIZE=256 -co OVERVIEWS=AUTO`.

| File | What it is | Tests |
|---|---|---|
| `dem-4326.tif` | float32 COG, EPSG:4326, nodata -9999, 2 levels | the plain geographic case |
| `dem-utm12.tif` | the same surface in EPSG:32612 (metres), nodata at the edges and the hole | warp, UTM |
| `dem-3857.tif` | EPSG:3857 | the fast path (`mode: '3857'`) |
| `dem-albers.tif` | EPSG:5070 | an equal-area system |
| `dem-stateplane-ft.tif` | EPSG:3567, US survey feet | units, a state plane |
| `ortho-rgb.tif` | 3 bands, 8 bit, the surface through a colour ramp (nodata black) | a colour image |
| `ortho-u16.tif` | 4 bands, 16 bit | percentile stretch per band |
| `classes.tif` | 1 band, 8 bit, nodata 0, a colour table of 5 classes | paletted, legend, class values |
| `striped.tif` | float32 in EPSG:4326, deflate, **not tiled** | the browser conversion to a COG |
| `no-overviews.tif` | tiled, 40,000 x 40,000 cells, UTM 12N, written sparse (49 KB) | refused zoomed out, plain message |
| `not-georeferenced.tif` | a plain 200 x 200 image, no georeferencing, not tiled | "not georeferenced" message |
| `world-file.tif` + `.tfw` | 200 x 200 RGB, georeferenced only by a world file | "world file not read yet" message |

What the tiler (cog-tiler-wasm 0.5.0) says about them (spike, 2026-10-26): the COGs open; `striped.tif`,
`not-georeferenced.tif` and `world-file.tif` all fail first with "header: Corrupt image data at layout: image is striped,
not tiled; tile range streaming requires a tiled COG" (so the open path reads the header for georeferencing before it
converts); `no-overviews.tif` opens and then fails to draw with "window 40000x40000 on level 0 is too large to read (limit
16777216 samples); this raster has no overviews ...". The 8.8 GB range-read file is not committed:
`npm run large-data -- --raster` writes `tests/.large-data/raster-big.tif` (30,000 x 30,000 float32 COG, about 4.9 GB).
