# Test fixtures

Most files predate spec 007 and are hand-made or exported from QGIS. The
sections below cover the generated ones.

## Spec 007 fixtures

Generated by `npm run large-data -- --fixtures` (`scripts/large-data.mjs`):
synthetic parcels across Utah, 10,000 rows each, EPSG:4326. Regenerate a
file by deleting it and re-running the command, which needs a native DuckDB
CLI and, for the derived files, GDAL's `ogr2ogr`.

| File | Size | Rows | How |
|---|---|---|---|
| `parcels-10k.parquet` | 1.9 MB | 10,000 | DuckDB; GeoParquet with a `bbox` covering struct, Hilbert-sorted |
| `parcels-10k-nobbox.parquet` | 1.6 MB | 10,000 | same rows, no covering column (exercises the one-scan bbox index) |
| `parcels-10k.fgb` | 3.6 MB | 10,000 | `ogr2ogr -f FlatGeobuf -lco SPATIAL_INDEX=YES` |
| `parcels-10k.geojson` | 5.0 MB | 10,000 | `ogr2ogr -f GeoJSON -lco COORDINATE_PRECISION=6` |
| `sample.pmtiles` | 2.1 MB | n/a (tiles) | `ogr2ogr -f PMTiles -dsco MINZOOM=4 -dsco MAXZOOM=10` (GDAL 3.13) |

Columns: `parcel_id`, `parcel_code`, `zone`, `acres`, `value`, `year_built`, `geom`
(plus `bbox` in `parcels-10k.parquet`).

The large-file versions (762 MB to 5 GB) live in the gitignored
`tests/.large-data/`, from `npm run large-data`.

## Spec 008 fixtures

Generated by `node scripts/fixtures-008.mjs` (native DuckDB CLI plus GDAL's
`ogr2ogr`). Delete a file to regenerate it.

| File | Rows | Purpose |
|---|---|---|
| `wide-50.parquet` | 200 points | 50 columns of text, integer, double, boolean, date and long-named columns (column chooser, filters, Shapefile field renames) |
| `buildings-10k.parquet` | 10,000 squares in Salt Lake City | `height_m` with 200 nulls and 400 zero or negative values (extrusion "drawn flat" count), `use` |
| `mixed-types.geojson` | 2 points + 2 polygons | Mixed geometry (Shapefile per-type split) |
| `three-layers.gpkg` | 180 / 3 / 3 | Layers `countries`, `city points`, `lookup_table` (no geometry) |
| `two.gdb/` | 2 layers | File Geodatabase, to check the "not supported" message |
| `gapped-ids.gpkg` | 12 / 5 / 3 | `zones` (ids 101, 103, …, 123; date and boolean columns), `stops` (ids 1..5), `notes` (no geometry, ids 7, 9, 11): GeoPackage ids that don't run 1..N (research §16) |
| `cube-network.sqlite` | 8 / 8 / 3 | SpatiaLite shaped like a Cube 7 network, EPSG:26912: `cubedb__BY__node` keyed by `n` (1, 2, 3, 10, 11, 12, 105, 106), `cubedb__BY__link` (`a`, `b`), `cubedb__BY__transit_mode` (no geometry) |

## Spec 009 fixtures

Generated by `node scripts/fixtures-009.mjs` (plain Node, seeded, so the
output is identical on every run). Delete a file to regenerate it.

| File | Rows | Purpose |
|---|---|---|
| `roads-traffic.geojson` | 2,000 lines | `functional_class` (5 values), `aadt` (log-normal, 50 nulls), `lanes` (1–4): color by one column, width by another |
| `counties-bivariate.geojson` | 600 grid polygons | `poverty_rate` and `obesity_rate` (correlated; 24 rows null in one of them), `name`: bivariate maps |

The sample dataset (`apps/web/public/sample/us-counties.parquet`, copied to
`apps/vscode-ext/sample/`) comes from `node scripts/sample-data.mjs`; see
THIRD-PARTY-NOTICES.md.
